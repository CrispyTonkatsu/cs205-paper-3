\subsection{Software Reliability}
As discussed in the technical section, AI utilizes the relationship between the provided prompt and the relationships it can build with the data to generate the code snippet. There is a major issue in this generation process, it doesn't perform logical reasoning in order to ensure that the code is correct. Tools like Claude utilize the added knowledge of the database, compiler errors and program output to ensure the program performs what is desired. However, this poses a critical issue, there is no guarantee that the side effects that stem from the lines being executed (such as memory allocation, pointer dereferencing, etc) don't harm the project or the users. This can be seen in several cases where the models are not trained with code of the quality desired, which in turn leads to bugs \cite{ai-bugs-paper}.

In the lens of act utilitarianism, there are also major concerns. If the goal is to maximize utility, creating infrastructure that fails to consistently deliver can reduce the overall benefits provided to the consumers. When the software written using GenAI is delivered to millions of people, the benefits that the engineers and corporate leads receive do not outweigh the downsides of the consumer base. In another framing, if the benefits were to be mainly monetary, the damages to society end up costing more in the long term, be it through the increase in electricity \cite{electricity-use} or the damage caused by failures in the delivered products \cite{replit-database-delete}. In the latter case, the accountability chain is also not clearly defined as to who is responsible or why the error happened as it could be a GenAI hallucination or user error in the prompt. This can cause major issues when trying to resolve the damages caused to the users and other individuals.
